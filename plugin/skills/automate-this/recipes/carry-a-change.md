# Recipe: Carry a change across documents

## When it fits

One change (a new date, a renamed offering, a policy update) has to show up in every document that mentions it.

## What to ask

- What exactly changed: the old wording or value and the new one.
- Why it changed and who approved it, so the edits can say so.

## Inputs and checks

- The documents from the sources list, read through a connected service or as copies in the inbox.

## Facts step

Useful when the documents are files: find every place the old value appears and count them per document.

## The result

- The change, described once in one sentence.
- Every affected document from the sources list, with each place that needs an edit.
- A draft edit for each place: the current text and the proposed text.
- Documents checked with no change needed, so nothing looks skipped.
- Never edit the documents directly. Say where each draft goes.
- End with "Sources:" listing every document checked.

## Checklist items to include

- Every document on the sources list was checked and is listed.
- Every place with the old value has a draft edit.
- No document was changed directly.

## Numbers

When the change is a number, copy the new value exactly as approved.

## Watch out for

- The old value said in different words: search for those too and list them.
- Documents not on the sources list: mention any the person names, and offer to add them.

## Example requests

- "The launch moved to March. Update everything that mentions it."
- "We renamed this offering. Find every document that needs changing."
