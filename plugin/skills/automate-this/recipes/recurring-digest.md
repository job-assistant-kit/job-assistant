# Recipe: Recurring digest

## When it fits

The person regularly sums up what changed (in a tracker, a list, a set of documents) since the last time, on a fixed rhythm.

## What to ask

- How often: daily, weekly, monthly, or quarterly? This sets the tool's rhythm.
- What counts as a change worth reporting?
- Who reads it?

## Inputs and checks

- This period's file and last period's file, or one file with a date column. List the required columns.

## Facts step

Required. Compare this period with the last: new items, removed items, changed fields, and counts of each. Keep the item names in the fact notes.

## The result

- A short opening: the period covered and the size of the change.
- New, changed, and removed items, grouped the way the reader thinks about them.
- Items that need attention first.
- End with "Sources:" naming both files and their dates.

## Checklist items to include

- States the period covered.
- Every new, changed, and removed item from the facts step appears.
- Counts match the facts step.

## Numbers

Set `exec_numbers: true` when the digest goes to leaders.

## Watch out for

- A missing last-period file: say the comparison is not possible this time instead of treating everything as new.
- Rhythm: a quarterly digest is not overdue after a few quiet weeks.

## Example requests

- "Give me the weekly changes in the tracker."
- "What changed in the offering list this month?"
